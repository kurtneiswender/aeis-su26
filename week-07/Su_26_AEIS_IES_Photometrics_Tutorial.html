Overview

Two Front-Ends, One Photometric Truth

Every accurate lighting calculation — in any software — starts from the same artifact: the manufacturer’s IES file. It is the luminaire’s photometric “score,” describing the candela in every direction plus the rated lumens and input watts. Revit and LightStanza are just two readers of that one file. This tutorial walks both.

§ 01

Photometrics in Ninety Seconds

Before any software: four quantities, and the one rule that ties them to a calculation. You met these in Week 6 — here they are as the inputs and outputs of the tools.

QuantityUnitWhat it isWhere it shows up
Luminous fluxlumen (lm)Total light a source emits, all directionsThe IES file’s rated/delivered lumens — the Φ you calculate with
Luminous intensitycandela (cd)Flux aimed in one directionThe candela grid inside the IES file — the polar distribution
Illuminancefootcandle / luxLight arriving on a surfaceWhat the calc outputs on your grid — your design target
Luminancecd/m² (nit)Light leaving a surface toward the eyePerceived brightness & glare — what false-color renders show
You design to illuminance (the footcandle target); the eye judges luminance. The software calculates the first and lets you see the second — never confuse the number you hit with the brightness people feel.

Two lumen numbers — don’t mix them

  • Lamp lumens — what the bare source emits.
  • Delivered (fixture) lumens — what actually leaves the housing after the lens and reflector. This is what the IES file reports and what the calc uses.
  • Always design with delivered lumens — the Φ in E = (N·Φ·CU·LLF)/A.

Light Loss Factor (LLF)

  • A multiplier (typ. 0.70–0.85) for dirt accumulation and lamp aging over time.
  • Both Revit and LightStanza expose it per fixture — LightStanza’s default is 0.82.
  • “Maintained” illuminance = with LLF applied. That’s what you report.
The hand calc still rules. The lumen method from Week 6 gives you the average you expect before you open any software. Run it first — then the simulation in § 04 either confirms it or tells you something the average couldn’t see. A simulation you can’t sanity-check by hand is a simulation you can’t trust.
§ 02

Get the Right IES File

No real IES file, no real calculation. A fixture without photometric data simply cannot contribute to a lighting result — the software has nothing to distribute. Start every fixture choice by finding its .ies file and its spec/cut sheet on the manufacturer’s product page.

Where to download

  • The manufacturer’s product page — look for a Downloads / Photometrics tab.
  • Acuity (Lithonia, Gotham), Signify (Philips), Cooper, Cree, Zumtobel, Selux — all publish IES.
  • Course shortlist starts at Lightology; more manufacturer links are posted on Canvas.
  • Search pattern: [brand] [model code] IES download.

Grab both, match them

  • Download the .ies file and the cut sheet — you need both for the deliverable.
  • The IES filename usually contains the product code; confirm it matches the sheet.
  • From the sheet, record: delivered lumens, input watts, CCT, CRI, distribution type, mounting.

What’s inside the file

An IES file is plain text. You don’t edit it by hand, but knowing its fields tells you whether a calc will be right.

Candela values
Intensity at a grid of vertical & horizontal angles — the photometric web. This is the distribution “shape.”
Rated lumens
Total delivered flux. Some tools recompute lumens from the candela grid; a mismatch with the spec sheet is worth a second look.
Input watts
The electrical load this fixture draws — the number your Week 7 connected-load tally and Week 8 panel need.
Luminous dimensions
The physical size of the light-emitting area. Set these accurately — a zero/point source produces calculation and rendering artifacts.
Photometry type
Absolute (LED — candela are real, fixed) vs. relative (scaled to a lamp lumen value you set). Most modern LED IES files are absolute; don’t override their lumens.
Verify before you trust it. Open the IES in the tool’s viewer and look at the polar plot: a downlight should show a downward cone, a wall-wash an asymmetric lobe, a linear fixture a longitudinal spread. If the shape is wrong, you have the wrong file — or it’s aimed wrong (fixed in § 04).
§ 03 · Path A

Revit — Place Luminaires & Assign Photometrics

Revit is where your fixtures live on the real model and where the luminaire schedule — a graded Act III deliverable — is built. The job here: place lighting-fixture families, give each one a photometric web, set its lumens / watts / color / loss factor, and schedule it.

  1. Load a lighting-fixture family with a defined light source

    Use Insert → Load Family (or a manufacturer’s Revit family). The family must contain a Light Source — in the Family Editor, Create → Light Source, with the source placed below the fixture opening so housing geometry doesn’t clip it. Families with no light source cannot contribute to a calculation.

  2. Place fixtures on a host

    Architecture/Systems → Component (or the Lighting Fixture tool). Place on the ceiling plane or a face. For a regular layout, place one and use Copy / Array at your target on-center spacing (from the lumen method). Work in a reflected ceiling plan so you’re placing where the light actually is.

  3. Assign the IES photometric web

    Select the fixture → Edit Type → the Photometrics group. Set Photometric Web File to your .ies. This replaces Revit’s generic distribution with the real candela web. The Light Source shape should read Photometric Web.

  4. Set intensity, color, and loss factor

    Still in the Photometrics group, confirm:

    • Initial Intensity — lumens (or candela / watts). For absolute LED files, leave the IES value; don’t inflate it.
    • Initial Color — the Color Temperature (CCT, e.g. 3000 K) so renders read warm/neutral correctly.
    • Light Loss Factor — 0.70–0.85 for a maintained result.
    • Wattage (in the family’s electrical parameters) — needed for the load column, not for the light calc.
  5. Build the luminaire schedule

    View → Schedules → Schedule/Quantities → Lighting Fixtures. Add fields: Type Mark, Family and Type, Photometric Web File, Initial Intensity (lumens), CCT, Wattage, and Count. This is your Act III luminaire schedule — one row per type. Add a calculated Count × Wattage field for the connected load.

  6. Get an illuminance result from Revit

    Three options, increasing rigor:

    • Render (View → Render, photometric/absolute exposure) — a qualitative look at distribution and brightness, not a measured grid.
    • Insight Lighting analysis (Analyze → Lighting, cloud) — quantitative false-color illuminance at a workplane, in footcandles/lux. Good for a native check.
    • ElumTools (third-party add-in) — full point-by-point illuminance inside Revit if your firm has it.

    For this course, the rigorous engine is LightStanza — so most of you will place + schedule in Revit, then hand the model to LightStanza (§ 04) for the calc and the false-color map you submit.

Tag rooms before you export. LightStanza builds its calculation grids from Revit Rooms or Spaces. Place Rooms/Spaces in the areas you want analyzed (seating, lobby, stage) before syncing — ungridded areas get no result.
§ 04 · Path B

LightStanza — Calculate the Illuminance

LightStanza is the calc engine. There are two ways in: sync from Revit (most of you), or build natively in LightStanza. Past the import, both run the same Grid Illuminance calculation.

Route 1 — Sync from Revit (the plugin)

  1. Export the model

    Add-Ins → LightStanza → Export. In the Export Window → Other Settings, choose the spatial type the grids follow — Rooms, Spaces, or Areas — and set the Calc Grid Height (workplane, e.g. 30″ / 2.5 ft). Horizontal illuminance grids generate automatically per Room/Space.

  2. Check what came across

    Two schedules ride along: “LightStanza Luminaires” (the fixtures in the model) and “LightStanza Report” (the full illuminance matrix, after you calc). Materials and fixture types map automatically — review them.

  3. Confirm / reassign IES files

    Open the IES / Family Manager. For each luminaire type, verify the assigned .ies or upload the correct one (directly, or from your team library). This is where the photometric web becomes real for the calc.

Route 2 — Build natively in LightStanza

  1. Upload IES files

    In the Luminaires panel, open the IES Manager → Add IES File (upload your download) or pick one from the team library. The viewer shows the candela polar plot and total lumens — confirm the shape.

  2. Place fixtures on the 2D plan

    Switch to a 2D lighting plan via the level dropdown. Add Fixture, choose the IES type, then click to place. Right-click a fixture for Copy, Mirror, Duplicate, Replace, Array, Rotate, Align, and Aim; nudge with arrow keys. Build a regular grid at your target spacing.

  3. Set mounting height & loss factor

    Per type, set mounting Height above floor, aiming (tilt/rotation) for adjustable fixtures, and LLF (default 0.82). Color/CCT here is for visualization and does not change the calculated illuminance.

Position the IES inside the housing

This is the step people skip — and it’s the most common reason a map looks wrong. The light source must sit where the light actually leaves the fixture, aimed the right way.

  1. Open the IES editor

    Click the three dots under the luminaire type → View/Edit IES File (also reachable from the IES/Family Manager).

  2. Reposition & rotate relative to the fixture

    Use Edit IES Position Relative to Fixture to move the source in X/Y/Z so housing geometry doesn’t block it, and Edit IES Rotation Relative to Fixture to correct aiming:

    • Ceiling-mounted: a 90° rotation usually points the web down correctly.
    • Wall-mounted: 0° is the usual start.
    • It depends on the file’s own coordinate system — confirm against the 3D view.

    Set the luminous dimensions to match the real aperture; avoid zeros (point-source artifacts).

Run the calculation

  1. New → Grid Illuminance

    In the Activity Bar, New → Grid Illuminance. Select your luminaire group and the calc grid. Set:

    • Unit: Footcandle (imperial) or Lux.
    • Point spacing: finer = more detail, slower.
    • Quality: Draft / High / Very High — High for design.
    • Emergency lighting checkbox — toggle on for the egress-only run (egress fixtures only, ~1 fc path target).

    Click Run. Electric calcs are fast — iterate freely.

Daylight + electric don’t run as one

LightStanza calculates daylighting and electric lighting separately. To tell the combined story, run each and compare in the comparison view:

  • Strong-sDA zones (from Act II) get daylight-dimming controls — electric load there drops toward zero in daytime.
  • Weak-sDA zones need full electric — these drive your connected-load number for Week 7.
  • Mark the daylight-fill vs. electric-fill zones on your annotated plan.
§ 05

Read the Map, Reconcile the Number

The result is a false-color illuminance plan plus min / max / average and a uniformity ratio. Your job is to read it against two things: the IES target for the space, and your own hand-calc average from Week 6.

  1. Read the false-color result

    Click the activity card to overlay the grid on the model. Use False Color mode — adjust the luminance/illuminance bounds and toggle log scale so the range fits your numbers. Turn on Contour Lines to trace specific footcandle thresholds (e.g. the 1 fc egress line).

  2. Check the average and the worst corner

    The panel reports min, max, and average fc plus uniformity. A healthy average with an 8 fc corner under the balcony is still a problem — uniformity is the value the average hides. Note both.

  3. Compare to the IES target

    Hold the average against the recommended maintained level for the space (table below). Over, under, or on target — and is the minimum acceptable for egress and task?

  4. Reconcile with the hand calc

    Put the simulated average next to your Week 6 E = (N·Φ·CU·LLF)/A result. If they agree, you’ve earned confidence in both. If they don’t, the gap is the finding — chase it down (next section). Write one line explaining the agreement or the gap; that sentence is what the rubric rewards.

  5. Export the proof

    Download the report from the activity card, or pull the LightStanza Report calc matrix. Drop the false-color image into the editable PowerPoint report sheet template. You can also export the luminaire schedule back to Revit or to DXF to overlay on your plan.

§ 06

When the Map Looks Wrong

Most bad results trace to a handful of causes. Work this table before you redesign anything — the fix is usually data, not the layout.

SymptomLikely causeFix
Flat / all one colorNo real photometric web, or generic distributionAssign the manufacturer .ies; confirm the polar plot in the viewer
Much too darkIES blocked by housing, or wrong aimingReposition the source in X/Y/Z; rotate (90° ceiling / 0° wall) so the web faces the room
Hot point / artifactsZero luminous dimensions (point source)Set real luminous dimensions to match the aperture
Average right, corners darkSpacing too wide for the distributionTighten on-center spacing or add a supplemental layer; check uniformity
No grid / no result in a roomRoom/Space not placed before exportAdd Revit Rooms/Spaces, re-export; or draw the grid manually in LightStanza
Lumens disagree with cut sheetRelative vs. absolute photometry confusionFor absolute LED files, don’t override lumens; trust the IES
Glass / layers missing (Rhino route)Surfaces didn’t export with materialsModel glazing as distinct surfaces; export Collada with layers, re-check materials
Sim ≠ hand calcOptimistic CU, wrong reflectances, or aimingRe-check surface reflectances and CU assumption; verify IES orientation; then trust the sim
Tool trouble is not a reason to fall behind. If the LightStanza electric module fights you, a Revit Insight lighting analysis (or a documented hand-calc with a render) is an accepted substitute for the weekly — flag it the same way we did for the daylight tools. Email the instructor your specific glitch so it can go to LightStanza support.
§ 07

How This Feeds Your Deliverable

This tutorial is the engine behind the Act III lighting set. Three of the things you submit come straight out of it.

Act III · Lighting set · built across Weeks 6–8

What you produce with these tools

  • Luminaire schedule — one row per type from Revit: product, distribution, delivered Φ, input W, CCT, CRI, mounting, qty. Real fixtures, real IES files.
  • Verified illuminance — a LightStanza false-color map for your primary space, with average, minimum, and uniformity, compared to the IES target and your hand-calc E, plus a one-line reconciliation.
  • Connected load + LPD — Σ(qty × input W) from the schedule’s watts column, divided by area — the Week 7 number that becomes the Week 8 panel and LPD check.
  • Decision Log entry — one fixture, aiming, or layout choice that the false-color map caused you to confirm or revise.
