§ 01

Session Objectives.

By the end of this week — between the recorded lecture and the live Q&A — each student should be able to:

  • State their RT60 target by program type and cite the published range it comes from.
  • Calculate RT60 by hand using both Sabine and Eyring at 500 Hz, 1 kHz, and 2 kHz using their own room geometry and material assignments.
  • Run the aeis_rt60.py script in Rhino and read the HTML output report.
  • Compare script output to hand calculation and either confirm agreement within ±0.2 s or explain the discrepancy.
  • Identify the dominant absorptive surface in their room by area × coefficient and know whether to add or remove absorption to hit target.

§ 03

RT60 — Reference Card.

Key facts from the pre-recorded lecture, condensed for the live session and your hand calculation. Use the Tutorial document for full derivations.

RT60 Targets by Program Type — Mid-frequency (500 Hz – 2 kHz)
Program Target range (s) Rationale
Speech-primary 0.8 – 1.2 s Short reverb preserves consonant intelligibility. Lecture halls, courtrooms, houses of worship (sermon-primary).
Mixed program 1.4 – 1.8 s Compromise between speech clarity and musical warmth. Multipurpose auditoriums, community halls.
Music-primary 1.8 – 2.2 s Longer reverb supports harmonic blend. Orchestral and choral halls. Speech intelligibility sacrificed at the far end.
Opera 1.3 – 1.6 s Hybrid: singers project over orchestra; text intelligibility still matters. Tighter than orchestral.
Sabine Equation — use for rooms with ᾱ < 0.20
RT60 = 0.049 × V / A
V
= room volume (ft³)
A
= total absorption (sabins) = Σ ( Sᵢ × αᵢ ) for each surface
αᵢ
= absorption coefficient at the octave band of interest
Sᵢ
= surface area (ft²)
Eyring Equation — use for rooms with ᾱ ≥ 0.20 (more accurate for absorptive halls)
RT60 = 0.049 × V / [ –S × ln(1 – ᾱ) ]
S
= total room surface area (ft²)
ᾱ
= mean absorption coefficient = A / S
ln
= natural logarithm — use a calculator; ln(1–0.30) = ln(0.70) ≈ –0.357

Rule of thumb: if your Sabine and Eyring results diverge by more than 0.3 s, your mean absorption is above 0.25 and Eyring is the number to trust. The script reports both.

Key Insight Volume is not the dominant variable — absorption is. Two rooms with the same volume but different materials can differ by a full second of RT60. Your material choices this week are not cosmetic; they are the primary acoustic lever you have at this stage of the project.

§ 05

Script Debugging.

Read this before class. Most errors fall into one of six categories. If your error matches one here, fix it before the live session — you do not need to wait for Q&A to unblock yourself.

Error / Symptom Cause Fix
Script runs but reports 0 surfaces found or RT60 = 0 Layer names don't match the AEIS_ convention. Hyphens instead of underscores, wrong case, missing prefix, or surfaces are on sublayers. Check each surface layer in Rhino. Must be exactly AEIS_MATERIAL_KEY — uppercase, underscores, no spaces. Rename via Properties panel or Layer dialog. Run script again.
Script runs but RT60 result is wildly off (e.g., 0.02 s or 45 s) Surfaces assigned to highly absorptive or reflective materials don't match their physical role, or a single very large surface is on the wrong layer (e.g., the site plane accidentally included). Check your total absorption A = Σ(S × α). A very large slab (site ground, background surface) with α = 1.00 will dominate. Delete or exclude non-room geometry from AEIS_ layers.
AttributeError: Point3d has no attribute 't' or similar RayShoot error Version mismatch — an older script version assumed RayShoot returned floats. The current script handles this correctly. Confirm you are using the version posted in the Canvas module (filename: aeis_rt60.py, not aeis_rt60_old.py). Re-download from Canvas if uncertain.
SyntaxError or garbled output on first line Encoding issue — Rhino's IronPython 2.7 requires an explicit UTF-8 declaration if the file was edited in an external editor that added a BOM. Open the .py file in a plain text editor (TextEdit on Mac — plain text mode; Notepad on Windows). Confirm the first line is exactly: # -*- coding: utf-8 -*- with no invisible characters before it. Save and re-run.
No source point — script errors or skips ray trace The source point is missing, on the wrong layer, or is a curve/surface object rather than a Point object. In Rhino: draw a Point (not a dot or a surface vertex) at stage center, approximately 5 ft above the floor. Place it on layer AEIS_SOURCE. Confirm object type in Properties: must say Point.
Script runs, HTML report saves, but PNG viewport capture fails or is blank Viewport capture requires a visible Rhino window and an active perspective or named view. Running Rhino minimized or via RemoteDesktop can cause this. Maximize Rhino before running the script. Switch to the Perspective viewport. The ray lines (colored by energy on layer AEIS_RAYS) must be visible. Run the script from the command line, not from an external terminal.
Correct Eyring output but large divergence from hand calculation Not a bug — usually a modeling discrepancy. Most common: hand calc used a different volume estimate, audience area was not modeled in Rhino, or a material key was approximated in the hand calc but is different in the script's lookup table. Note the discrepancy, measure volume in Rhino (Volume command), and compare to your hand-calc V. Check that your hand-calc material coefficients match the script's table (Week 1 §07 layer table). A note in your Act I submission explaining the discrepancy satisfies the rubric.

§ 07

Q&A Protocol.

The live session is student-driven. To make it useful for everyone, follow this structure.

Concept Questions

  • Ask in chat first — instructor will address in batches. Similar questions will be grouped.
  • Good: "Why does Eyring give a lower RT60 than Sabine for the same room?" Good: "How do I find α for a material not on the layer list?"
  • Questions from the recording are welcome — there are no dumb questions in Week 2.

Script Debugging

  • Check §05 first. If your error is in that table, fix it before the session.
  • To share your screen: unmute, say "I have a script error," and share your Rhino window. Keep the Layer panel visible.
  • Post your error text in chat before screen sharing — it speeds diagnosis.
